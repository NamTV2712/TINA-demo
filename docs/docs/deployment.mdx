TINA runs **in your own environment** — open-source, self-hostable, and able to run with no egress. Data, recordings, and
agent state stay on infrastructure you control. This page is the Docker Compose path; the other two
supported shapes are [TINA Lite](/deployment-lite) (one container, no Docker socket) and
[Kubernetes](/deployment-kubernetes) (Helm, a Pod per bot).

## Quick start (Docker Compose)

Prerequisites: macOS with OrbStack or Docker Desktop, or Linux with **Docker Engine ≥ v26** and
Compose supporting `up --wait`; also `git`, `make`, and Python **3.10+**. Building from source needs
about **8 vCPUs / 16 GB RAM**.

For a new local install, use the CLI with a private env file outside the checkout. The repository's
default `.env` is Dotenvx-encrypted and its private key is not part of a public clone:

```bash
cd /path/to/TINA
make cli-install
export PATH="$HOME/.local/bin:$PATH"
mkdir -p "$HOME/.config/tina"
export ENV_FILE="$HOME/.config/tina/.env"
tina setup --dry-run
tina setup
```

Setup creates a separate `tina-local` project with new volumes and prints the active URLs and API
key. It does not adopt or stop existing deployments. To rebuild an already configured instance, use
`make plan` then `make all` from its checkout; that path requires Dotenvx and the matching private
`.env.keys` file. `make all` preserves Compose volumes.

The default local ports are `13000` for the Terminal and `18056` for the API gateway. A bot needs a
reachable transcription backend, and agent chat needs a configured model. For this repository's
Gipformer 1.5 service, install the pinned model assets and follow the [Gipformer Compose guide](https://github.com/poor-frog/TINA-KT/blob/main/deploy/transcription/gipformer/README.md).
Production Terminal sign-in requires configured Google or Microsoft OAuth; see
[Terminal login](#terminal-login-google-or-microsoft). The deployment mints and prints an API key
when it is ready; treat it as a secret.

## The stack

| Service | Role |
|---|---|
| **gateway** (`:18056`) | the one front door — auth, scopes, routing |
| **admin-api** | users + API keys |
| **meeting-api** | bots, transcripts, **recordings** (to object storage) |
| **runtime** | spawns bot + agent **containers** on demand (via the Docker socket) |
| **agent-api** | the [agent control plane](/api/agent) — dispatch, chat, routines, events |
| **terminal** (`:13000`) | the web workbench — proxies `/ws` → gateway and REST/login → agent-api/admin-api |
| redis (Valkey) · postgres · **storage** (versitygw) | bus + scheduler · metadata · recordings, stored as plain files in the `storage-data` volume |

The **bot is not a long-running service** — the [runtime](/core/runtime) spawns a browser container per
meeting (`BROWSER_IMAGE`) and an agent container per dispatch (`AGENT_IMAGE`), then reaps them. `make
all` builds the browser image from source before starting the stack; use `make bot` to rebuild it alone.

## Configuration

- **Transcription (STT)** — `TRANSCRIPTION_SERVICE_URL` / `TRANSCRIPTION_SERVICE_TOKEN`. Unset →
  default `POST /bots` answers **503** (refuse loud). Capture-only: set `TRANSCRIBE_ENABLED=false`
  or pass `{"transcribe_enabled": false}` on the spawn. See
  [Configuration](/configuration#transcription-stt).
- **Object storage** — the `storage` service runs versitygw (`versity/versitygw`, Apache-2.0,
  pinned by tag and digest), an S3 server whose POSIX backend keeps every recording as a plain file
  in the `storage-data` volume. meeting-api reaches it over S3 with the `MINIO_*` settings (the
  variable names are unchanged): `MINIO_ENDPOINT=storage:9000`, and `MINIO_ACCESS_KEY` /
  `MINIO_SECRET_KEY` are the server's root credentials, so change both before exposing the stack.
  The one-shot `storage-init` ensures the bucket exists and verifies a PUT/GET/DELETE probe under
  `.tina-storage-init/` before meeting-api starts. The storage S3 port is published on loopback only, at
  `STORAGE_HOST_PORT` (default `18900`). To keep recordings in your own S3 instead, point
  `S3_ENDPOINT` (or `MINIO_ENDPOINT`) at it; the same readiness check applies
  ([Configuration](/configuration#database-storage)). Back the volume up
  with an attribute-preserving copy ([Recordings → Backups](/how-to/recordings#backups)).
  Upgrading a stack that ran MinIO: old recordings stay in the old volume and do not play back
  from the new storage until copied with `make -C deploy/compose migrate-storage`. Update the old
  `.env` endpoint as described in [Where your recordings live now](/upgrade-from-minio).
- **Agent inference** — bring your own: point the agent at your endpoint so no inference leaves the
  network (`TINA_AGENT_MODEL` / mounted credentials).
- **Secrets** — `ADMIN_TOKEN`, `INTERNAL_API_SECRET`, DB credentials. Set real values before exposing.

### Terminal login (Google or Microsoft)

Production Terminal login requires a configured OAuth provider. Set the provider's client ID and
secret in the private env file, set `NEXTAUTH_URL` to the Terminal's browser URL, and register the
matching callback URI with the provider. For the default local port, Google uses
`http://127.0.0.1:13000/api/auth/callback/google`; Microsoft uses
`http://127.0.0.1:13000/api/auth/callback/microsoft`. After changing these values, restart the
Terminal container with the same `ENV_FILE` selected. On a new instance, its first successful
sign-in claims the administrator role. Passwordless test login is development-only.

For local Google sign-in, the private env file includes:

```dotenv
NEXTAUTH_URL=http://127.0.0.1:13000
GOOGLE_CLIENT_ID=your-client-id
GOOGLE_CLIENT_SECRET=your-client-secret
```

Replace the values with the OAuth client from Google Cloud, use the exact callback URI above, then
run `tina restart terminal --yes` while the same `ENV_FILE` is exported. Use the Microsoft client
fields instead if you sign in with Microsoft.

## Transcription backends

The meeting API sends audio to the OpenAI-compatible endpoint configured by
`TRANSCRIPTION_SERVICE_URL`. The stack does not start a model unless its profile or external service
is configured. This repository includes an optional CPU-only **Gipformer 1.5 + FSMN-VAD** Compose
service under the `asr` profile; install its pinned assets and follow the
[Gipformer Compose guide](https://github.com/poor-frog/TINA-KT/blob/main/deploy/transcription/gipformer/README.md).
The separate `deploy/transcription` stack provides Faster-Whisper for GPU or CPU deployments.
Language is detected per transcription window and stamped on each segment; force a single language
via the bot request's `language` (see [Send a bot](/how-to/send-a-bot)).

### Run the separate Faster-Whisper unit

Stand it up wherever a GPU lives (the same host or a dedicated GPU box):

```bash
cd deploy/transcription
cp .env.example .env          # set MODEL_SIZE, API_TOKEN, TRANSCRIPTION_LB_PORT
docker compose up -d          # GPU (needs nvidia-container-toolkit)
# no GPU? CPU variant (slower, use a smaller model):
docker compose -f docker-compose.cpu.yml up -d
curl http://localhost:8083/health   # waits on the model load
```

**CPU concurrency:** the worker's admission cap (`MAX_ACTIVE_REQUESTS`) defaults to `20` only when
`DEVICE=cuda` (sized on an RTX 4090); on any other device (`cpu`, `auto`, `mps`) it defaults to `2`,
because 20 CPU jobs sharing the cores never finish and the worker deadlocks while still reporting
healthy. Set `MAX_ACTIVE_REQUESTS` explicitly if your hardware differs; an explicit value always wins.

Then point the main stack at it in `deploy/compose/.env`:

```bash
TRANSCRIPTION_SERVICE_URL=http://<gpu-host>:8083   # base URL; client appends /v1/audio/transcriptions
TRANSCRIPTION_SERVICE_TOKEN=<same as the unit's API_TOKEN>
```

**Which model id goes where:** the stack sends `TRANSCRIPTION_MODEL` as the OpenAI-compatible
`model` field on every request (unset → `whisper-1`). The **bundled unit ignores it** — pick its
model with the unit's own `MODEL_SIZE`. Backends that **validate** the field need the right id:
**Groq** → `whisper-large-v3-turbo`, **OpenAI** → `whisper-1` / `gpt-4o-transcribe`,
**vLLM/LiteLLM** → the exact served model name. Any OpenAI-compatible
`/v1/audio/transcriptions` endpoint works: set `TRANSCRIPTION_SERVICE_URL` to its base URL,
`TRANSCRIPTION_SERVICE_TOKEN` to its key, and `TRANSCRIPTION_MODEL` to the id it expects.

Now bots transcribe end-to-end: **bot → transcription service → segments → meeting-api `collector`
→ live fan-out**. Scale by adding workers (one GPU each) in the unit's `docker-compose.yml` +
`nginx.conf`.

## Publishing behind a reverse proxy

`make all` binds every service to `127.0.0.1` (loopback only). To expose the **terminal** at a public
hostname, put a TLS-terminating reverse proxy in front of the terminal port (`TERMINAL_PORT`, default
`13000`) and tell the terminal its public origin so auth cookies and OAuth callbacks are correct:

```bash
# deploy/compose/.env
NEXTAUTH_URL=https://your-host.example.com
NEXTAUTH_SECRET=<a strong random secret>   # don't ship the dev default
```

An nginx vhost (the terminal proxies `/ws` to the gateway itself, so the proxy only needs standard
WebSocket-upgrade headers):

```nginx
server {
    listen 443 ssl;
    server_name your-host.example.com;
    ssl_certificate     /etc/letsencrypt/live/your-host.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-host.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:13000;       # TERMINAL_PORT
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;   # terminal /ws → gateway
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}
```

If you publish the **gateway** (`:18056`) through a reverse proxy, set `GUARD_TRUSTED_PROXIES` to the
proxy's IP and have the proxy forward the real client IP. The edge guard is **on by default**, so this
applies unless you have explicitly opted out:

```nginx
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

Without it, every request keys to the proxy IP — one global rate-limit/ban bucket shared by all
clients, so one abuser throttles everyone. The gateway honors the `X-Forwarded-For` chain only from an
IP named in `GUARD_TRUSTED_PROXIES` (it reads the rightmost entry); a spoofed header from any other
source is ignored, so it cannot rotate an abuser's budget. See
[Configuration → Gateway edge protection](/configuration#gateway-edge-protection).

The terminal carries its own Google/Microsoft OAuth login, so the proxy needs no auth of its own.

## No egress

Everything runs inside your perimeter: gateway + services + redis/postgres/storage on your host, the
[transcription unit](#transcription-the-separate-gpu-unit) on your own GPU or CPU, **BYO inference**,
recordings in your object storage. A bundled STT unit means the audio path never calls out — the
posture the regulated verticals ask for.

We have not run an install on a genuinely disconnected network, so we do not claim one: what a
procurement review can hold us to is self-hosted with no egress, not a certified air gap. On
**Kubernetes** the chart does not yet expose `TRANSCRIPTION_MODEL` as a value — see
[No-egress clusters](/deployment-kubernetes#no-egress-clusters).

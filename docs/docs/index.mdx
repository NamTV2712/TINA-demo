licensed under Apache-2.0. TINA has not yet been verified as a deployed system.

<Note>

## What it does

- **Captures meetings natively** — real-time transcripts from [Google Meet, Zoom, and Teams](/core/meetings). Configure an OpenAI-compatible STT service; Jitsi support is experimental.
- **Meets you at your calendar** — [connect a secret ICS address](/how-to/calendar-sync) and upcoming meetings import automatically; the bot [auto-joins](/core/meetings#auto-join--scheduled-means-the-bot-comes) each one at start. [Plan a meeting](/how-to/plan-a-meeting) ahead and share its prep workspace with the people you're meeting.
- **Turns knowledge into code** — meetings and emails become a living, Markdown [workspace](/concepts#workspace) that agents treat as their working directory.
- **Runs agents safely** — every [agent](/core/agents) executes in an isolated, ephemeral [container](/concepts#container) with brokered tools.
- **Self-hosted deployment** — run the full stack with [Docker Compose](/deployment) or Kubernetes.
- **Stays in your environment** — open-source, self-hostable, and able to run with [no egress](/deployment#no-egress) via bring-your-own inference and a bundled STT unit. Recordings and agent state never leave infrastructure you control.

## Try it

For a fresh install, follow the [Quickstart](/quickstart). From an already configured checkout,
preview and then build/start its selected deployment:

```bash
cd /path/to/TINA
make plan     # inspect the selected project and services
make all      # build, start, and print the API key + URLs
```

The default API is at `http://127.0.0.1:18056` (gateway) and the Terminal web
workbench at `http://127.0.0.1:13000`. Full options — no egress, bring-your-own
inference — in [Deployment](/deployment).

`make all` prints an API key when the self-hosted stack is ready.

## Why TINA

AI reshaped software development: a CLI agent on a Linux box is now enough to build
software. TINA scales that same execution model to knowledge work — meetings and emails
as the source, agents as the workers, your infrastructure as the sandbox.

And the codebase itself is built for that world. Every service is a **modular monolith**:
a [module owns exactly one concern](/concepts#module) and is the single source of truth for
it; modules join only through [sealed contracts](/concepts#contract) that CI refuses to let
drift; every unit ships its code, its adversarial tests, and the goldens that validate it —
with fixtures collected from real meetings. That is what makes the system tractable for
human contributors **and** for AI agents working on it — debug any module in isolation, or
any chain of modules at the scale a bug lives at. The map: [Modules & Seams](/architecture/modules).

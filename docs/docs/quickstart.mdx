This walkthrough starts the configured TINA deployment: its Compose project, Google sign-in,
Gipformer speech recognition, and agent services. It preserves the deployment's existing data.

## Prerequisites

- macOS with OrbStack or Docker Desktop, or Linux with Docker Engine **≥ v26** and Docker Compose
  supporting `up --wait`. Building the source stack needs about **8 vCPUs / 16 GB RAM**.
- `git`, `make`, Python **3.10+**, a local Docker context, Dotenvx, and the private `.env.keys` file
  matching this repository's encrypted `deploy/compose/.env`.
- The Gipformer model assets, installed in step 4 below.

## 1. Clone the repository

```bash
git clone https://github.com/poor-frog/TINA.git
cd TINA
```

## 2. Install Dotenvx

On macOS:

```bash
brew tap dotenvx/brew
brew trust dotenvx/brew
brew install dotenvx
```

Or use npm: `npm install --global @dotenvx/dotenvx`.

## 3. Provide the matching private key

Copy the existing `.env.keys` from your private password manager or secure backup to the repository
root. It must contain the `DOTENV_PRIVATE_KEY` that matches `deploy/compose/.env`; a new key cannot
decrypt the existing file. Keep `.env.keys` private. Git ignores it, but do not paste the key into a
command, commit, issue, or documentation.

## 4. Install Gipformer model assets

```bash
python3 deploy/transcription/gipformer/install-models.py
```

This downloads and checksum-verifies the pinned Gipformer 1.5 and FSMN-VAD files under
`deploy/transcription/models/gipformer-fsmn`. The current encrypted Compose config enables the
`automation,asr,dashboard` profiles and connects the bot to `http://gipformer:8000`.

## 5. Preview and start

```bash
make plan     # read-only: confirm the project and selected profiles
make all      # build, start, wait for readiness, and print the API key + URLs
```

This starts the existing `tina-production` project and retains its database, recordings, and
workspaces. The current configured URLs are Terminal `http://127.0.0.1:23000` and API gateway
`http://127.0.0.1:28056`; the command output is authoritative if the deployment config changes.
The matching Google OAuth credentials are already in the encrypted config. On a new database, the
first successful sign-in becomes administrator.

<Note>
Keep both the private Dotenvx key and the API key printed by `make all` secret. If you do not have
the matching Dotenvx key, do not invent a replacement: use the separate [fresh-install guide](/deployment#quick-start-docker-compose).
</Note>

## 2. First win — capture a meeting (UI)

<Steps>
  <Step title="Open the terminal">
    Open the Terminal URL printed by `make all` and sign in with Google.
  </Step>
  <Step title="Configure speech recognition">
    The `asr` Compose profile starts Gipformer 1.5 + FSMN-VAD. If your account has a transcription
    preference that overrides the platform default, select Gipformer under Settings → Models. See
    the [Gipformer guide](https://github.com/poor-frog/TINA/blob/main/deploy/transcription/gipformer/README.md)
    and [transcription configuration](/configuration#transcription-stt).
  </Step>
  <Step title="Send a bot to a meeting">
    Start a Google Meet, Zoom, or Teams call, copy the join URL, and add it from the UI. A bot joins
    the call as a participant — no plugin, no host setup.
  </Step>
  <Step title="Watch the transcript stream">
    Speak. Speaker-attributed segments appear live, draft-then-confirmed, as the meeting runs.
  </Step>
</Steps>

## 2′. Same thing over the API

Use the API key printed by `make all`, then send a bot and read the transcript:

```bash
# keep this key private
export API_KEY=tina_...
export API_BASE=http://127.0.0.1:28056

# send a bot — native_meeting_id is the id from the join URL (e.g. abc-defg-hij)
curl -X POST "$API_BASE/bots" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"platform":"google_meet","native_meeting_id":"abc-defg-hij","bot_name":"TINA"}'

# read the transcript (poll while the meeting runs)
curl -H "X-API-Key: $API_KEY" \
  "$API_BASE/transcripts/google_meet/abc-defg-hij"
```

Full surface — translation, WebSocket streaming, recordings, stopping the bot — in the
[Meetings API](/api/meetings).

## 3. Second win — ask your workspace a question

Every captured meeting compiles into your **workspace** — a Markdown knowledge base an agent reads
and writes like a developer in a repo. Configure an agent provider/model under Settings → Models,
then chat with it:

```bash
curl -N -X POST "$API_BASE/agent/chat" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"prompt":"What did we decide in my last meeting?"}'
```

The response streams back as Server-Sent Events — `message-delta` frames carry the reply, `commit`
frames mark anything the agent recorded. See the [Agent API](/api/agent).

## 4. Third win — connect your calendar

Stop pasting links: give TINA your calendar's **secret ICS address** (Google Calendar → Settings →
your calendar → *Integrate calendar* → **Secret address in iCal format**, the `…/private-…/basic.ics`
one — *not* the public address above it). Every upcoming event imports; Meet/Zoom/Teams events are
armed for auto-join and link-less events remain visible until you add a link. On a Google
**Workspace** domain the secret-address field may need a one-time admin unlock
([how](/how-to/calendar-sync#1-find-your-secret-ics-address)).

```bash
curl -X POST "$API_BASE/user/calendars" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"name":"Work","ics_url":"https://calendar.google.com/calendar/ical/…/basic.ics","auto_join":true,"bot_name":"Work Notes"}'
```

Run `POST /user/calendars/{calendar_id}/sync` for an immediate result, or wait for the background
cycle. Full walkthrough: [Calendar sync](/how-to/calendar-sync). Complete endpoint reference:
[Calendar API](/api/calendar).

# Local token-streaming PoC — 2026-10-24

## Outcome

**The cached Qwen3-ASR-0.6B decoder can emit real token callbacks on this Mac.** Captions were
produced while `generate()` was still running. For the same complete input audio, all nine
fixture pairs produced exactly the same final text with and without the streamer callback.

**The paced growing-window prototype is not ready to replace live TINA ASR.** It repeatedly
encodes accumulated audio, can fall behind the source clock, and degraded final text on this
small pilot. TINA's production backend/settings were not changed.

## Setup and coverage

- Host: Apple M4 Max, 36 GiB unified RAM; MPS/bfloat16, automatic CPU inference fallback disabled.
- Qwen cache revision: `5eb144179a02acc5e5ba31e748d22b0cf3e303b0`.
- Runtime: qwen-asr 0.0.6, Transformers 4.57.6, PyTorch 2.14.1.
- Six cached human-recorded FLEURS clips: three Vietnamese and three English, each ≤15 seconds.
- Two VI→EN/EN→VI concatenation controls, not natural code switching, plus one silent fixture.
- Four modes per fixture: batch, token callbacks on the complete clip, paced 1 s and paced 2 s.
- Completed run: **36/36 cases, zero decode failures**. Silence produced no text in any mode.
- Results: `~/tina-test-rig/qwen-token-poc-20261024-03/`; report, raw events, scored results,
  package/source fingerprints and before/after production checks are retained there.
- Attempt 01 stopped during fixture preparation. Attempt 02 stopped when a production loopback
  dependency became unavailable. Those partial attempts are retained separately and are not
  spliced into the complete run. The cause of that availability change is not established here.

The host was in normal interactive use, not an isolated benchmark machine; repository checks
also ran concurrently during part of the completed experiment. OS/I/O/GPU load, warm-history and
thermal state are confounders. These are descriptive PoC observations, not latency guarantees.

Concatenation-control WER was 37.5% for complete audio and 52.083% for the paced prototype.
Those controls therefore do not establish adequate bilingual/code-switching behavior. These
figures are not comparable to earlier full FunASR/FSMN benchmarks: samples, VAD and runtime
conditions differ. Vietnamese WER is whitespace/syllable-style and preserves accents.

## Memory

- Peak sampled model-worker RSS: **713.7 MiB** (100 ms sampling, includes descendants).
- Largest observed **post-window** MPS driver allocation: **1919.8 MiB**.
- Metal numbers are snapshots, not transient GPU peaks. Do not add RSS and driver allocation
  as disjoint physical memory. The existing production model remained resident separately.
- Runtime initialization, including Python/Torch/Qwen imports and model placement, took 17.29 s;
  that is not a clean cold-weight-only startup measurement.

## Next integration gate

Before selecting this path for production, address obsolete-window backlog/coalescing, utterance
endpointing, long speech and multiple sources, and validate natural VI/EN code switching. Preserve
PCM ACK/recovery, per-source clocks, provisional-tail replacement and canonical edit/Restore
protection. A backend with incremental acoustic processing or a better optimized local runtime
should be compared on the same frozen inputs in a controlled sequential run.

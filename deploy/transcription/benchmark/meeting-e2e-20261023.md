# Synthetic Vietnamese–English meeting E2E — 2026-10-23

## Scope and verdict

Executed the real Qwen/FSMN → Sherpa-ONNX diarization → Vietnamese MFA → canonical →
Conversation Window/extraction path over **69.47 seconds, three synthetic voices and 15 turns**.
Linh speaks Vietnamese; Daniel and Samantha speak English. Audio has two long pauses and no
speaker overlap. These are cross-turn language switches, not natural within-speaker code switching.

The final verification run passes source preservation, owner checks, exact evidence/revision,
word-bound validation, edit/restore, revision-conflict and actual word-attribution rename checks.
**Functional integrity passes; speaker/alignment/extraction quality still has material failures.**

Meeting API handlers run through an in-process HTTP transport with the production PostgreSQL and
recording adapters. PostgreSQL uses a fresh disposable DB and MinIO a UUID test prefix. Every model
request goes to the real existing worker. Browser, gateway, audio device and Google Meet transport
are excluded. Temporary databases and audio objects were removed; fixtures/results remain outside Git.

## Descriptive measurements

Both repetitions produced identical ASR text and model annotation results. The exploratory run's
rename selected an identity with no word attribution, so that check was tightened and the full
pipeline rerun. Only the final run is evidence for word-attribution rename behavior (two actual words).

Each ASR latency sample is an 8-second window, except the final 5.47-second window. There are only
nine samples per run: these p50/p95 values describe this replay, not production latency estimates.
Capture-window waiting is separate from inference/persistence. The host was shared with other
applications; these were not isolated hardware benchmarks.

Worker telemetry after run 03 shows the two slow ASR requests spent approximately **25.41 s and
23.51 s in inference**; the nine ASR queue waits were **0.45–3.26 ms**. Queue backlog is therefore
not the explanation for those individual slow requests. No hardware root cause is established.

## Recognition, speaker and timestamp failures

- ASR: **10/159 normalized whitespace tokens wrong (6.29% WER)**, **45/634 characters wrong
  (7.10% CER)**. Accents are preserved. Nine errors are deletions; one is a substitution. Missing
  suffixes include Vietnamese “tiếp tục kiểm thử” and English “report before review” / “release date”
  across the fixed-window boundaries. This harness has no cross-window reconciliation.
- Diarization returned **two nonempty clusters for three source voices**, despite supplying the known
  count of three. A global best injective label mapping scores **72.08% correct reference speech
  time**, with **27.92% confusion**, zero missed scored speech and 0.15 s false alarms in gaps.
  Scoring uses trimmed TTS utterance intervals, a 250 ms collar and 10 ms frames; it is not an AMI
  DER benchmark or hand-labelled phonetic activity ground truth.
- MFA returned all **150 raw tokens**; only **72 (48%)** have times, the other **78** remain explicitly
  unaligned. Among tokens matching reference text, **66/70 VI** and **5/79 EN** have times. The
  Vietnamese-only model does not provide sufficient English coverage in this mixed fixture.
- All aligned times stayed inside their saved source segment and were monotone. One matched
  Vietnamese token (“tôi”) has its midpoint **1154 ms outside its reference utterance**. Therefore
  legal segment bounds do not prove correct word timing. There is no independent word-level
  reference; word-boundary MAE is **not measurable** here.
- The 95.77% matched-token speaker accuracy concerns only 71 timed/matched tokens (66 VI, five EN).
  It excludes the many untimed English tokens and must not be presented as overall speaker accuracy.

## Canonical, evidence and mutation checks

The final run produced **nine durable segments, two conversation windows and 11 extraction candidates**.

Passed against the real isolated PostgreSQL/MinIO state:

1. Raw ASR text and audio SHA-256 remain unchanged after analysis and mutations.
2. Canonical word text preserves every raw token, with null timestamps for OOV/unaligned words.
3. Every candidate quote equals its source segment's accepted text and current revision.
4. A different owner receives 404 for canonical, memory and alignment.
5. Renaming an acoustic speaker updates two actually attributed words and the canonical revision.
6. Correcting a segment removes its old candidate evidence and invalidates word timing for rewritten
   text; a stale expected revision returns 409.
7. Restore returns raw text and its aligned words, with text revision advanced to two.
8. API snapshots equal stored projections, and outbox events contain no text/quotes.

Exact evidence establishes provenance, **not semantic correctness**. The candidate list includes
spurious `fact` labels for “We decided to keep the current release…” and a segment mentioning
“bản hiện tại”: the rule treats “current/hiện tại” anywhere in the segment as a fact cue. A valid
English decision in the same segment as a preceding Vietnamese negation is also suppressed by the
rule's segment-wide prefix-negation check. No extraction precision/recall is claimed.
